# S4：真实 S-57 LNDARE 接入

日期：2026-10-29。S3 验收通过后实施；本阶段止于陆地，不进入 S5–S7。

## 文件与接口

- `include/veylaxis/vgds/S57.hpp`、`src/vgds/S57.cpp`：readS57、S57Report、真实陆地测试范围选择。
- `Configuration.hpp/.cpp`：读取同一份配置，选择 mock 或 s57 来源；ServiceSetup 只有 STL 数据。
- `config/vgds-s57.json`：真实 ENC 输入、可配置 GridSpec 和缓存、OSGB 开关。
- `ServiceMain.cpp` 与 `streaming/Viewer.cpp`：统一配置入口，打印来源/更新/加载统计。Viewer 用父变换将初始区域移到局部场景原点，不改变网格或 TileID。
- `tests/vgds/S57Tests.cpp`、Test 分发和 CMake：真实数据自动化及来源文件脱离测试。
- `scripts/test-vgds-service.ps1`：不依赖 Qt/海洋 SDK 的服务测试配置，可加 `-NoOsgb` 排除 OSG。
- README、解决方案入口和三阶段说明文档。

`ITileProvider`、`TileRequest`、`TilePackage`、TileClient 与 TileManager 生命周期保持相同，切换数据源不需要为真实 ENC 编写另一套主程序加载逻辑。原天空、海洋和 viewer.cpp 没有修改。

## 读取和来源

只读打开 S57 驱动，显式 `UPDATES=APPLY`、`LNAM_REFS=ON`。检查基础文件 `.000` 与同名单元的数字更新扩展名，要求连续；保存每个输入文件 SHA-256。读取 DSID edition/update，核对更新号与现有序列；GDAL 返回读取错误时失败，不把失败当空区块。

当前实测：US2EC04M，edition=0，update=1，基础文件和 `.001` 均参与来源版本。原始图层 WGS84/EPSG:4326，显式传统 GIS 轴序，经 GDAL/PROJ 转为配置中的米制投影。拒绝 EPSG:4326 等角度单位目标网格。

来源对象 ID 是 `cell:objectClass:LNAM`；若缺 LNAM，回退为带 edition 的 RCID，而非只用 FID 或坐标哈希。保留 RCID、RVER、LNAM、原始属性、source_fid、cell、源文件列表、edition/update、原始 CRS、目标 CRS 和内容版本。数值列表在 Core 的 string-list 属性中保留各项，并另记原字段类型；不支持的属性类型保留其字符串表达及类型。

一次启动加载并投影 LNDARE 和 COALNE，之后 LocalService 只查询内存快照。当前实际读取：

| 图层与几何 | 数量 | 行为 |
| --- | ---: | --- |
| LNDARE 面 | 260 | 保留轮廓，裁剪后生成可选 OSGB |
| LNDARE 点 | 310 | 按半开网格归属返回数据，不假造面模型 |
| LNDARE 线 | 20 | 保留线几何，不假造面模型 |
| COALNE 线 | 347 | 独立 coastline 图层，不拿它们强行闭合成岛屿 |
| 本单元未支持/丢弃的几何 | 0 | 测试显式检查 |

在其他 ENC 中出现尚未支持的几何类型会记入 unsupportedGeometries，不能据此宣称所有 S57 几何都已覆盖。

S57 原始面边也可能沿海图覆盖界延伸，不能一律当成真实海岸。原始 LNDARE 面边仅在独立 COALNE 线段证实后标 Geographic，未证实的源边保留 Unknown；裁剪新增边仍标 ArtificialClip。Builder 只沿 Geographic 边生成侧壁，Unknown 和 ArtificialClip 均不生成。确认使用配置网格的内存桶索引，不引入新的空间数据库。当前数据确认 38,403 条地理边，97 条源边保留 Unknown；不会把这 97 条边默认为海岸。

## 构建、查看与测试

```powershell
./scripts/build.ps1
./scripts/test.ps1
./scripts/test-vgds.ps1
./scripts/test-vgds-service.ps1 -NoOsgb

. ./scripts/runtime.ps1
./build/Release/Test.exe --vgds-s57

./scripts/view-vgds.ps1 -Config config/vgds-s57.json -LandOnly
./scripts/view-vgds.ps1 -Config config/vgds-s57.json -Tour
```

真实服务 CLI 使用同一个 `VgdsService --config config/vgds-s57.json`，请求 TileID (-5,4)、layers:[land,coastline] 即可，不需修改客户端协议。切换为 config/vgds-mock.json 可回到模拟来源。

实际验收覆盖：

- 源文件、更新、CRS、来源身份、原始字段及所有 590 个 LNDARE 对象的几何类型计数。
- 选中对象的三块面积守恒，3×3 所有相邻块的公共边界来源与区间一致。
- 语义包结构、重复响应确定性、9 次生成/9 次缓存命中及真实陆地 OSGB 反读。
- 把两份 ENC **复制到临时目录**后读取，删除这两份测试副本，仍能请求/生成 3×3；原始数据文件未删除或修改。
- 原 S3 TileClient/TileManager 不变，真实陆地连续跨两个中心边界并返回，加载/卸载无失败，析构场景清空。
- 非米制 CRS、缺失输入返回错误。

机器记录在 `output/vgds/s4-validation.json`；关闭 OSGB 的独立配置写 `s4-validation-no-osgb.json`，两者互不覆盖。记录包含本次测量的启动与九块冷请求/命中时间、OSGB 字节数、来源版本和接缝误差。时间依赖系统状态，不是帧率或生产性能保证。

最终构建与测试：正常主程序/Test 构建成功，CTest 9/9 通过；不依赖 Qt/海洋 SDK 的 SERVICE_ONLY+OSGB=ON 配置 4/4 通过；SERVICE_ONLY+OSGB=OFF 配置 3/3 通过；原 VGDS_ONLY 配置 1/1（401 项检查）通过。根 Veylaxis.slnx 也通过 MSBuild Release/x64 构建。

最终服务配置测试记录约 430 ms 启动加载/投影/岸线分类，九次冷请求加九次命中（含 OSGB 反读和一致性验证）约 292 ms，九个 OSGB 总计 23109 字节。这是本次小范围平顶陆地 fixture 的测量，不适用于海底重建成本预测。

真实窗口检查已完成：output/vgds-s4-land.png 是陆地独立视图，output/vgds-s4-marine.png / vgds-s4-marine-underwater.png 为既有 SilverLining/Triton 的海面/水下视图；程序正常退出，海面相机 Z=60 m，水下 Z=-12 m，XYZ×1。水下视图不含本阶段未生成的海底模型。

## 限制与未解决问题

- 这是 1:675000 海图的地理轮廓。1 km 分块及显示密度不代表米级原始资料精度。
- 陆地 Z=12 m 为统一估算的显示平顶，底部 0 m，XYZ 尺度 1:1；不是 S57 实测陆地高程，也没有重建山形。估算标识在 OSGB Builder 版本、节点元数据和文档中明确记录。海底仍使用原有独立成果，本阶段不新建真实数据海底。
- 97 条未证实源边保守保留 Unknown；没有自行补海岸、补侧壁或修复源数据拓扑。未来可结合 S57 边链及 mask 更精细解释。
- 仅单份 ENC 启动快照；更新原文件后需重启服务以建立新版本，不支持运行中热重载、多图幅拼接和完整覆盖区域 M_COVR。当前 Empty 不区分海图外无覆盖与图内无陆地。
- LNDARE 点/线保留数据但没有面模型；其他海事点状对象及其模型管理留给 S6。
- 缓存路径是本地静态文件地址，无 HTTP、远程文件传输、跨进程 TileClient 和磁盘容量淘汰；当前未实现生产级超时/抢占取消及总进程/显存基准。
